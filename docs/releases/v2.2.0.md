# v2.2.0

## Summary
- Adds PostgreSQL as an optional persistence backend alongside existing JSON storage.
- Introduces Repository Pattern with abstract interfaces and Strategy Pattern for runtime backend selection.
- Includes complete database schema, migration runner with auto database creation, and CI integration testing.

## Included Changes
- `persistence/interfaces.py`
  - Abstract base classes: `WalletLedgerRepository` and `SimulationRunRepository`.
- `persistence/factory.py`
  - Factory functions with lazy imports for backend selection via `PERSISTENCE_BACKEND` env var.
- `persistence/pg_connection.py`
  - `ThreadedConnectionPool` singleton with context manager and auto commit/rollback.
- `persistence/pg_multiuser_wallet_store.py`
  - Full PostgreSQL implementation of `WalletLedgerRepository` with normalized table upserts and revision tracking.
- `persistence/pg_simulation_store.py`
  - Full PostgreSQL implementation of `SimulationRunRepository` with JSONB payload storage.
- `persistence/multiuser_wallet_store.py`
  - `JsonMultiUserWalletStore` now inherits from `WalletLedgerRepository` ABC.
- `persistence/simulation_store.py`
  - `JsonSimulationStore` now inherits from `SimulationRunRepository` ABC.
- `config/settings.py`
  - Frozen dataclass reading `PERSISTENCE_BACKEND`, `DATABASE_URL`, `PG_POOL_MIN`, `PG_POOL_MAX` from env vars.
- `migrations/versions/V001__initial_schema.sql`
  - Complete DDL: wallet domain (users, wallets, policies, risk_profiles, nonces, utxos, transfers, alerts, revisions), simulation domain (simulation_runs with JSONB), traceability domain (lots, certificates, logistics_events, compliance_profiles with seed data).
  - All monetary columns use `NUMERIC(28,8)` matching Decimal 8-place precision.
  - Partial indexes on transfers (daily filter) and certificates (active only).
  - Enum types for wallet_model, transfer_type, transfer_status, risk_profile, alert_type, alert_severity, compliance_status.
- `migrations/migrate.py`
  - Forward-only SQL migration runner with auto database creation via `pg_database` check.
- `scripts/multiuser_wallet_cli.py`
  - Refactored to use `create_wallet_store()` factory. Alert box word-wrap for long messages.
- `scripts/multiuser_terminal.py`
  - Refactored to use `create_wallet_store()` factory. Alert box word-wrap for long messages.
- `scripts/blockchain_models_simulator.py`
  - Refactored to use `create_simulation_store()` factory.
- `.github/workflows/ci-pr.yml`
  - Added integration job with PostgreSQL 16 service container.
  - Unit tests now exclude `integration` marker by default.
- `.github/workflows/ci-main.yml`
  - Updated test command and artifact archive to include new packages.
- Tests
  - `tests/test_persistence_interfaces.py` verifying ABC inheritance and abstract method contracts.
  - `tests/test_factory.py` verifying JSON default, path validation, and PG backend instantiation.
  - `tests/integration/test_pg_wallet_store.py` with save/load roundtrip and revision listing.
  - `tests/integration/test_pg_simulation_store.py` with CRUD and not-found cases.
  - `pytest.ini` updated with `integration` marker registration.
- `requirements.txt` and `requirements-dev.txt`
  - `psycopg2-binary>=2.9,<3` as optional dependency for PostgreSQL backend.

## Validation
- `py -m pytest -q -m "not integration"` — 73 passing, 2 skipped (PG tests without psycopg2)
- JSON default mode fully preserved — zero breaking changes to existing commands
- Integration tests designed for CI with PostgreSQL 16 service container

## Notes
- This release follows SemVer as a MINOR version because it adds a new backward-compatible feature (PostgreSQL persistence) without changing any existing public command contracts.
- JSON remains the default backend. PostgreSQL is activated by setting `PERSISTENCE_BACKEND=postgres` and `DATABASE_URL`.
