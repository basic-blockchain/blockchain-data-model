# v2.7.0

## Summary

- Wallet freeze/unfreeze: dual-mode (all wallets of a user, or a single wallet by ID).
- User ban: automatically freezes all wallets; unban optionally unfreezes.
- Admin sudo re-validation: moderation operations require JWT re-confirmation with 3-attempt limit.

## Included Changes

### `domain/auth.py`
- Permissions added: `FREEZE_WALLET`, `UNFREEZE_WALLET`, `BAN_USER`, `UNBAN_USER`.

### `domain/multiuser_wallet_ledger.py`
- `WalletRecord` extended with `frozen: bool = False`.
- `freeze_wallet()`, `unfreeze_wallet()`, `is_wallet_frozen()`: single-wallet or all-user-wallets mode.
- `ban_user()`: sets `banned=True`, freezes all wallets implicitly.
- `unban_user()`: clears `banned`, optionally unfreezes wallets.
- `is_user_banned()`.
- `transfer()`, `mint()`, `top_up()`: reject if source or target wallet is frozen.

### `migrations/versions/V007__user_ban_wallet_freeze.sql`
- `ALTER TABLE users ADD COLUMN banned BOOLEAN NOT NULL DEFAULT FALSE`.
- `ALTER TABLE wallets ADD COLUMN frozen BOOLEAN NOT NULL DEFAULT FALSE`.
- Partial indexes on `users(banned)` and `wallets(frozen)` where `true`.

### `persistence/pg_multiuser_wallet_store.py`
- Backward-compatible fetch/upsert for `banned` (users) and `frozen` (wallets) with `_column_exists` guard.

### `scripts/multiuser_wallet_cli.py`
- Subparsers: `freeze-wallet`, `unfreeze-wallet`, `ban-user`, `unban-user`.

### `scripts/multiuser_terminal.py`
- Section MODERACION (35-38) in ADMIN menu.
- `_require_admin_token()`: sudo prompt with JWT re-validation, 3 attempts, `refresh` keyword to re-authenticate.
- Login flow detects banned message and renders CUENTA SUSPENDIDA banner.

### `tests/`
- `tests/test_freeze_ban.py` (20 tests)
